## Objective
Wire up Datadog for logs, metrics, APM, and RUM. **Configure PHI scrubbing at the log shipper level — this is non-negotiable.** If a PHI field leaks into Datadog without BAA coverage for that exact data type, it's a breach. Belt-and-suspenders: BAA + scrubbing + no raw PHI in logs.

### 2. Initialize APM tracer (must be FIRST import)

`apps/crm-api/src/tracer.ts`:
```typescript
import tracer from "dd-trace";

tracer.init({
  service: "crm-api",
  env: process.env.NODE_ENV || "development",
  version: process.env.GIT_SHA || "dev",
  logInjection: true,           // trace IDs in logs
  runtimeMetrics: true,
  // CRITICAL: strip PHI from span tags
  tags: {
    "app.compliance": "hipaa",
  },
});

// Block specific headers from being captured in traces
tracer.use("http", {
  headers: [],  // explicitly empty — do NOT capture auth cookies, tokens
});

export default tracer;
```

In `apps/crm-api/src/index.ts`, import tracer FIRST:
```typescript
import "./tracer";  // MUST be first line
import { Hono } from "hono";
// ... rest of app
```

### 3. PHI scrubbing in log pipeline

This is the most important part. We use **Datadog's Sensitive Data Scanner** (enterprise feature) AND code-level scrubbing.

`packages/observability/src/scrubber.ts`:
```typescript
// Redact known PHI field names before sending to Datadog
const PHI_FIELDS = [
  "patient_name", "patientName", "patient_dob", "patientDob",
  "patient_mrn", "patientMrn", "patient_address", "patientAddress",
  "patient_member_id", "payerMemberId", "ssn", "dateOfBirth", "dob",
  "firstName", "lastName", "middleName", "fullName",
];

// Redact known PHI patterns
const PHI_PATTERNS = [
  /\b\d{3}-\d{2}-\d{4}\b/g,                    // SSN
  /\b\d{3}[- ]?\d{3}[- ]?\d{4}\b/g,            // Phone
  /\b[A-Z0-9]{9,12}\b/g,                        // Likely MRN (uppercase alphanumeric)
  /\b\d{4}[- ]?\d{4}[- ]?\d{4}[- ]?\d{4}\b/g,  // Card-like
];

export function scrubPHI(input: unknown): unknown {
  if (typeof input === "string") {
    let out = input;
    for (const p of PHI_PATTERNS) out = out.replace(p, "[REDACTED]");
    return out;
  }
  if (Array.isArray(input)) return input.map(scrubPHI);
  if (input && typeof input === "object") {
    const result: Record<string, unknown> = {};
    for (const [k, v] of Object.entries(input as Record<string, unknown>)) {
      if (PHI_FIELDS.some(f => f.toLowerCase() === k.toLowerCase())) {
        result[k] = "[REDACTED]";
      } else {
        result[k] = scrubPHI(v);
      }
    }
    return result;
  }
  return input;
}
```

### 4. Structured logger that scrubs before writing

`packages/observability/src/logger.ts`:
```typescript
import pino from "pino";
import { scrubPHI } from "./scrubber";

export const logger = pino({
  level: process.env.LOG_LEVEL || "info",
  formatters: {
    log: (obj) => scrubPHI(obj) as Record<string, unknown>,
  },
  serializers: {
    err: pino.stdSerializers.err,
    req: (req) => ({
      method: req.method,
      url: req.url,
      // Do NOT log headers (auth tokens)
    }),
  },
});
```

Use `logger` everywhere — never raw `console.log`.

### 5. Datadog Sensitive Data Scanner rules

In Datadog UI → Security → Sensitive Data Scanner → add rules:

| Rule name | Pattern | Action |
|---|---|---|
| US SSN | built-in SSN detector | Redact |
| US Phone | built-in phone detector | Redact |
| Email | built-in email detector | Partial redact (preserve domain) |
| Custom: MRN | `\b[A-Z0-9]{9,12}\b` in `patient.*` | Redact |
| Custom: Date of Birth | `\b(?:19\|20)\d{2}[-/]\d{2}[-/]\d{2}\b` | Redact |

Apply scope: all logs from `service:crm-api` and `service:crm-web`.

### 6. RUM (Real User Monitoring) — web frontend

`apps/crm-web/app/layout.tsx` (or a separate RUM init component):
```typescript
"use client";
import { datadogRum } from "@datadog/browser-rum";
import { useEffect } from "react";

export function DatadogRumInit() {
  useEffect(() => {
    datadogRum.init({
      applicationId: process.env.NEXT_PUBLIC_DD_RUM_APP_ID!,
      clientToken: process.env.NEXT_PUBLIC_DD_RUM_CLIENT_TOKEN!,
      site: "datadoghq.com",
      service: "crm-web",
      env: process.env.NEXT_PUBLIC_ENV,
      version: process.env.NEXT_PUBLIC_GIT_SHA,
      sessionSampleRate: 100,
      sessionReplaySampleRate: 20,   // partial replay sampling
      trackUserInteractions: true,
      trackResources: true,
      trackLongTasks: true,
      defaultPrivacyLevel: "mask",    // mask ALL by default (PHI-safe)
      allowedTracingUrls: [
        { match: /https:\/\/.*\.vercel\.app/, propagatorTypes: ["datadog"] },
      ],
    });
  }, []);
  return null;
}
```

**`defaultPrivacyLevel: "mask"` masks all user input in session replay.** Any field that should be visible (e.g., dashboard KPIs) can be explicitly unmasked with `data-dd-privacy="allow"`. Inverting the default is critical for HIPAA.

### 9. Dashboards + alerts (basic set)

Create one dashboard: **"Medical CRM Health"**
- Login success vs failure rate (last 1h)
- Referrals created per tenant (last 24h)
- p95 API latency
- RLS policy block count (**should always be 0 — alert if > 0**)
- Audit log write rate

Create alerts:
- RLS policy block count > 0 over 5 min → PagerDuty / email (critical)
- Auth failure rate > 10% over 10 min → warning
- p95 latency > 2s over 10 min → warning
- Any error log matching `phi` or `PHI` → immediate escalation

## Common issues

- **"No data in APM"** — tracer.ts must be the FIRST import, before any other module (including Hono)
- **RUM not appearing** — NEXT_PUBLIC_ prefix is required for browser-side env vars
- **Logs arrive but no trace IDs** — `logInjection: true` in tracer.init + pino configured with correlation
- **Sensitive Data Scanner not redacting** — rules apply to NEW logs only; test after rule creation
- **PHI showing up in replay** — session replay samples are stored in Datadog. If PHI leaked, **this is a breach event.** Purge session replays + notify compliance.
