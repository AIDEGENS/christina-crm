## Objective
Deploy `apps/crm-web` to Vercel dev environment. Confirm env vars are set, deployment is healthy, and the login flow works end-to-end.

## Approach

### Link the project

```bash
cd apps/crm-web
vercel login    # use work email; must be invited to Vercel Enterprise team
vercel link     # creates .vercel/project.json
```

Choose: Vercel Enterprise team (NOT personal scope).

### Configure build settings in vercel.json

`vercel.json` at monorepo root:
```json
{
  "version": 2,
  "installCommand": "pnpm install --frozen-lockfile",
  "buildCommand": "pnpm turbo build --filter=crm-web",
  "outputDirectory": "apps/crm-web/.next",
  "framework": "nextjs",
  "regions": ["sfo1"],
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Strict-Transport-Security", "value": "max-age=63072000; includeSubDomains; preload" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=(self)" }
      ]
    }
  ]
}
```

**Why `sfo1`:** San Francisco edge region is closest to us-west-1 (N. California RDS) → low latency + stays within California for data residency.

### Set environment variables in Vercel

Via CLI or dashboard. For dev environment:

```bash
# Database (from step 0.2 output)
vercel env add DATABASE_URL development

# WorkOS (from step 0.4)
vercel env add WORKOS_API_KEY development
vercel env add WORKOS_CLIENT_ID development
vercel env add WORKOS_COOKIE_PASSWORD development  # 32+ char random
vercel env add NEXT_PUBLIC_WORKOS_REDIRECT_URI development

# AWS (from step 0.2)
vercel env add AWS_REGION development  # us-west-1
vercel env add S3_BUCKET development
vercel env add KMS_KEY_ID development
vercel env add AWS_ACCESS_KEY_ID development      # or use IAM role if Vercel supports
vercel env add AWS_SECRET_ACCESS_KEY development

# App
vercel env add NEXT_PUBLIC_APP_URL development  # https://crm-web-dev.vercel.app
```

**Never** put secrets in `vercel.json` or commit them to the repo. Use Vercel's encrypted env var storage.

### Update WorkOS redirect URIs

In WorkOS dashboard:
- Add `https://<dev-deployment-url>.vercel.app/api/auth/callback` as a valid redirect URI
- Add the same for any preview deployments (use wildcard if supported)

### Deploy

```bash
# From monorepo root
vercel --prod=false   # deploys to dev/preview
# Or just: vercel
```

Vercel returns a deployment URL like `https://crm-web-abc123.vercel.app`.

### Test the deployment

1. Visit the deployment URL
2. Should redirect to `/login` (unauthenticated)
3. Click "Continue with SSO" — should go to WorkOS
4. Log in with the admin user provisioned in 0.4
5. Should land on `/dashboard` with "Hello, {email}"
6. Logout — should return to `/login`

### CI/CD for future pushes

`.github/workflows/deploy.yml`:
```yaml
name: Deploy
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm turbo lint typecheck
      - uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
          working-directory: ./
```

## Common issues

- **"Module not found: @crm/db"** — Vercel needs monorepo config. Ensure `vercel.json` `installCommand` uses pnpm and `buildCommand` uses Turborepo
- **"DATABASE_URL is not set"** — env vars set for `development` but deploying to `production` (or vice versa). Check env scope
- **WorkOS redirect URI mismatch** — add the Vercel URL to WorkOS dashboard exactly
- **RDS connection timeout** — RDS security group must allow Vercel IPs (temporary: 0.0.0.0/0 with password auth; tighten later)
- **Vercel Standard tier, not Enterprise** — Standard has NO BAA. Confirm team plan before deploying PHI paths.
