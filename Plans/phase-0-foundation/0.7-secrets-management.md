## Objective
Move every secret out of `.env` files and Vercel's UI-stored env vars into **Doppler**, which becomes the single source of truth. Doppler injects secrets at runtime via integrations with Vercel, GitHub Actions, and local dev. Prevents secret sprawl and accidental commits.

## Approach

### 1. Create Doppler project structure

In Doppler UI:
- Create project: `medical-crm`
- Environments: `dev`, `staging`, `prod`
- Configs per environment (Doppler's naming convention)

### 2. Migrate secrets into Doppler

For each env (start with dev), add these secrets:

**AWS (from step 0.2):**
```
AWS_REGION=us-west-1
AWS_ACCESS_KEY_ID=<from IAM user>
AWS_SECRET_ACCESS_KEY=<from IAM user>
S3_BUCKET=medical-crm-docs-dev-us-west-1
KMS_KEY_ID=<arn>
```

**Database (from step 0.2/0.3):**
```
DATABASE_URL=postgres://crm_admin:<password>@<endpoint>:5432/crm
DATABASE_URL_READONLY=<optional read replica>
```

**WorkOS (from step 0.4):**
```
WORKOS_API_KEY=sk_...
WORKOS_CLIENT_ID=client_...
WORKOS_COOKIE_PASSWORD=<32+ char random>
NEXT_PUBLIC_WORKOS_REDIRECT_URI=https://<vercel-url>/api/auth/callback
```

**Datadog (from step 0.6):**
```
DD_API_KEY=...
DD_APP_KEY=...
NEXT_PUBLIC_DD_RUM_APP_ID=...
NEXT_PUBLIC_DD_RUM_CLIENT_TOKEN=...
DD_ENV=dev
DD_SERVICE=crm
```

**App:**
```
NEXT_PUBLIC_APP_URL=https://<vercel-url>
NEXT_PUBLIC_ENV=dev
NODE_ENV=production
```

### 3. Local dev integration

Every dev runs commands through Doppler:

```bash
# Login once
doppler login
doppler setup   # in monorepo root; select project=medical-crm, config=dev

# Every dev command wrapped:
doppler run -- pnpm turbo dev
doppler run -- pnpm drizzle-kit push:pg
doppler run -- pnpm tsx packages/db/src/seed.ts
```

Alternative: shell alias `alias d='doppler run --'` → `d pnpm dev`.

### 4. Vercel integration

In Vercel dashboard → Project → Settings → Integrations → Doppler:
- Install Doppler integration
- Link `medical-crm/dev` → Vercel `Development`
- Link `medical-crm/staging` → Vercel `Preview`
- Link `medical-crm/prod` → Vercel `Production`

Doppler auto-syncs secrets to Vercel. **Delete the manually-added env vars from Vercel UI** to avoid drift.

### 5. GitHub Actions integration

In GitHub repo → Settings → Secrets → Actions, add ONE secret:
```
DOPPLER_TOKEN=<service account token from Doppler>
```

Update `.github/workflows/deploy.yml`:
```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dopplerhq/cli-action@v3
      - run: doppler run -- pnpm install
        env:
          DOPPLER_TOKEN: ${{ secrets.DOPPLER_TOKEN }}
      - run: doppler run -- pnpm turbo lint typecheck test
        env:
          DOPPLER_TOKEN: ${{ secrets.DOPPLER_TOKEN }}
```

### 6. Rotation policy

Schedule in a calendar (or automate later):
- **Quarterly:** rotate DB master password, AWS access keys, WorkOS API keys
- **Monthly:** rotate Doppler service tokens used in CI
- **On event:** rotate any secret that may have leaked (accidental log, Slack paste, etc.)

Rotation procedure:
1. Generate new secret in the source system (AWS, WorkOS, etc.)
2. Add to Doppler as `<NAME>_NEW`
3. Deploy → apps use `NAME_NEW`
4. Revoke old secret
5. Rename `NAME_NEW` → `NAME` in Doppler
6. Deploy

### 7. Doppler access control

- Service accounts: one per environment (`ci-dev`, `ci-prod`). Revocable.
- User access:
  - `clay@` — Owner (all environments)
  - Developers — Developer role (dev only)
  - Production access — Owner only + MFA required

### 8. Audit log

Doppler provides its own audit log. Review monthly:
- Who accessed prod secrets
- Failed authentication attempts
- Token creations / revocations

Export audit logs monthly into `s3://medical-crm-audit-us-west-1/doppler/` for 6-year retention compliance.

### 9. Hard rules

- **NEVER** commit `.env.local`, `.env.*`, `terraform.tfvars`
- **NEVER** paste secrets into Slack, email, or any chat
- **NEVER** include secrets in `console.log` or error messages (caught by PHI scrubber in 0.6, but double-layer)
- **NEVER** check secrets into Vercel UI manually — only via Doppler sync
- **NEVER** share Doppler login credentials; use SSO

## Common issues

- **"doppler: command not found"** — install Doppler CLI first (`brew install dopplerhq/cli/doppler`)
- **Vercel not receiving updated secrets** — Doppler integration sync is eventual; force resync in Vercel UI
- **Local `doppler run` asks to set up** — run `doppler setup` once per clone
- **Two places defining same secret** — Vercel UI value wins over Doppler if both exist; delete from Vercel UI
- **CI token has too much access** — create per-environment service tokens, scope them to one config
