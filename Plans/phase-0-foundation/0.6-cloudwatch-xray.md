# Step 0.6 — CloudWatch + X-Ray Observability (AWS-only)

## Status
SCAFFOLD — code written, user-blocked on AWS account + log group + X-Ray daemon.

## Supersedes
`0.6-datadog-observability.md` (deleted 2026-04-23). Datadog dropped to keep
the whole stack under one AWS BAA. See `AWS-ONLY-MIGRATION.md`.

## Objective
Server-side traces, logs, and metrics flow through AWS-native services with
PHI scrubbed before ingestion.

## Pieces

### Tracing — AWS X-Ray (DONE in Phase A)
`packages/observability/src/tracer.ts`:
- `aws-xray-sdk-core` initialized at first-import of the app entry.
- `captureHTTPsGlobal(https)` + `captureHTTPsGlobal(http)` patch outgoing
  HTTP(S) so every request is a downstream segment.
- `capturePostgres(pg)` patches the `pg` driver. Bound parameters NOT
  captured (SDK default; we do not set `AWS_XRAY_COLLECT_SQL_QUERIES`).
- `Segment.prototype.close` wrapped to strip query strings from
  `http.request.url` and replace with a `[REDACTED]` annotation.
- `NODE_ENV === 'test'` skips init.

`apps/api/src/tracer.ts` re-exports the package tracer as the literal first
line of the entry file. Order matters — anything imported before it is not
instrumented.

X-Ray daemon: the ECS task def runs the AWS Distro for OpenTelemetry (ADOT)
collector as a sidecar container listening on UDP 127.0.0.1:2000. SDK
defaults to that endpoint.

### Logs — CloudWatch Logs (DONE in Phase A)
`packages/observability/src/logger.ts` is unchanged from the Datadog era —
pino emits scrubbed JSON to stdout. The ECS task def's `awslogs` driver
ships stdout to the `/ecs/christina-crm/{web,api}` log groups. PHI scrubber
runs inside the pino `formatters.log` hook so redaction happens BEFORE the
byte leaves the process.

Log group configuration (Phase B terraform):
- Retention: 30 days for dev, 400 days for stg/prd (Medicare TPE review
  window).
- KMS-encrypted with `alias/medical-crm`.
- Subscription filter: pattern `"\"[REDACTED]\""` → metric filter counter
  so we alert if the scrubber ever matches downstream (redundant safety
  net — scrubber should have already masked it).

### Metrics — CloudWatch EMF (DONE in Phase A)
`packages/observability/src/metrics.ts` emits Embedded Metric Format JSON
lines to stdout. CloudWatch Logs' native EMF parser promotes the values to
CloudWatch Metrics under the `christina-crm` namespace.

Emit API:
- `increment(stat, tags?, value=1)` → Unit=Count
- `distribution(stat, value, tags?)` → Unit=Milliseconds, percentiles
  computed by CloudWatch from repeated samples.
- `gauge(stat, value, tags?)` → Unit=None.

PHI tag guard replicates scrubber subset (SSN, phone, email) to prevent
identifier leakage into metric dimensions. Fires a synthetic counter
`crm.observability.phi_in_tag` if the guard ever redacts.

### Frontend RUM — DEFERRED
Datadog RUM removed. CloudWatch RUM will be wired at pilot signing, not
before. Browser telemetry gap for Phase 0 is accepted; X-Ray server
traces + CloudWatch standard metrics cover the visibility bar.

## Tag doctrine (unchanged from Datadog era)
- `service` — crm-api | crm-web
- `env` — development | staging | production
- `route` — the API route template, never the full path (no IDs)
- `tenant` — tenant UUID, cardinality-bounded by the customer count

Never tag with: user ID, referral ID, MRN, phone, email. The PHI guard
in `metrics.ts` enforces this for the three most leaked shapes but the
compile-time discipline is on the caller.
