# Step 0.5 — ECS Fargate Deploy (AWS-only)

## Status
SCAFFOLD — code written, user-blocked on AWS account + BAA + terraform apply (Phase B).

## Prerequisites
- Step 0.1 completed
- Step 0.2 completed (RDS + KMS + S3 provisioned)
- Step 0.4 completed or in progress (WorkOS)
- AWS BAA signed (AWS Artifact click-sign, free)
- AWS CLI + Terraform configured locally

## Objective
Deploy `apps/web` and `apps/api` as two ECS Fargate services behind a single
ALB, with CloudFront in front of the web service. All images stored in ECR.
Secrets pulled from SSM at container boot.

## Approach

### Containers (DONE in Phase A)
- `apps/web/Dockerfile` — multi-stage Next.js 15 standalone, Node 20 alpine,
  non-root user, port 3000.
- `apps/api/Dockerfile` — multi-stage Hono + tsc, Node 20 alpine, non-root,
  port 3001.
- `.dockerignore` at repo root — excludes node_modules, .env, .next,
  .git, REF/, Plans/, docs/, .github/.

### Infra (Phase B terraform — NOT in Phase A)
Modules to be added under `infra/terraform/modules/`:

- `ecr/` — two repositories (`christina-crm-web`, `christina-crm-api`) with
  lifecycle policies (keep last 20 tags).
- `ecs/` — one cluster per env, two services, task defs with awslogs
  driver → `/ecs/christina-crm/{web,api}` log groups.
- `alb/` — one ALB per env, two target groups, host-based routing:
  `app.{env}.domain` → web target group, `api.{env}.domain` → api TG.
- `cloudfront/` — one distribution in front of the ALB for the web
  service. ACM cert provisioned in `us-east-1` (CloudFront requirement).
  Response headers policy adds HSTS (preload once domain is live),
  referrer-policy, permissions-policy. CSP stays in Next middleware.
- `ssm/` — parameter hierarchy + KMS key + per-service IAM read role.

### Deploy workflow (DONE in Phase A)
`.github/workflows/deploy.yml` uses:
- `aws-actions/configure-aws-credentials@v4` — OIDC, no long-lived keys.
- `aws-actions/amazon-ecr-login@v2` — login to ECR.
- `docker/build-push-action@v5` — build + push, GHA cache.
- `aws-actions/amazon-ecs-render-task-definition@v1` — swap image URI in
  `infra/ecs/task-def-{web,api}.json`.
- `aws-actions/amazon-ecs-deploy-task-definition@v1` — force new deployment,
  wait for service stability.

Matrix builds `web` and `api` in parallel.

### DNS
- `app.dev.domain` → CloudFront distribution (Alias A record in Route53).
- `api.dev.domain` → ALB directly (no CloudFront; APIs bypass the CDN).

### Health checks
- Web: ALB hits `/` with 10s timeout, 2s interval, 2 healthy / 3 unhealthy.
- API: ALB hits `/health` (unauthenticated, returns `{ ok: true }`).

## User-blocked runbook (Phase B)

See `SECRETS-HANDOFF.md` and `AWS-ONLY-MIGRATION.md` § Phase B. Summary:

1. Sign AWS BAA in AWS Artifact.
2. Create `gha-deploy` IAM role with OIDC trust policy pinned to this repo.
3. Add `AWS_ACCOUNT_ID` as a GitHub repo secret.
4. `terraform apply` the ECR / ECS / ALB / CloudFront / SSM modules per env.
5. Populate SSM via `./scripts/ssm-setup.sh ${env}`.
6. `gh workflow run deploy.yml -f env=dev` — first deploy.
7. Configure Route53 records.
8. Smoke: ALB DNS responds, container pulls secrets from SSM, CloudWatch
   Logs receive the `API running` line, X-Ray trace map shows web → api.
