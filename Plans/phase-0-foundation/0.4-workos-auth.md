### Session + tenant selection

When a user logs in via WorkOS, map to a `crm.users` row:

`apps/crm-web/app/api/auth/callback/route.ts` (or in the AuthKit handler):

```typescript
import { getUser } from "@workos-inc/authkit-nextjs";
import { db } from "@crm/db";

// After WorkOS auth, upsert into crm.users and resolve tenant access
export async function POST() {
  const { user } = await getUser();
  if (!user) return Response.redirect("/login");

  // Find crm.users rows for this WorkOS user
  const userRows = await db.query.users.findMany({
    where: (u, { eq }) => eq(u.workosUserId, user.id),
    with: { tenant: true },
  });

  if (userRows.length === 0) {
    // First login — admin must provision user first
    return Response.redirect("/unauthorized");
  }

  // Default to first tenant; user can switch later
  const defaultTenant = userRows[0].tenantId;
  // Set in session cookie (iron-session)

  return Response.redirect("/dashboard");
}
```

### Tenant context middleware (API side)

Every API request needs `app.current_tenant` set for RLS. Create middleware:

`packages/auth/src/tenantContext.ts`:
```typescript
import { db } from "@crm/db";
import type { AuthSession } from "./types";

export async function withTenantContext<T>(
  session: AuthSession,
  fn: () => Promise<T>
): Promise<T> {
  // Use a transaction so SET LOCAL is scoped
  return await db.transaction(async (tx) => {
    await tx.execute(
      `SET LOCAL app.current_tenant = '${session.tenantId}'`
    );
    // Note: use parameter binding in real code; inline shown for clarity.
    // SET LOCAL does not accept $1 params — sanitize tenantId as UUID.
    return await fn();
  });
}
```

### Role-based access helper

`packages/auth/src/roles.ts`:
```typescript
import type { Role } from "./types";

export const roleHierarchy: Record<Role, number> = {
  viewer: 0,
  bd_rep: 1,
  intake: 2,
  admin: 3,
};

export function hasRole(userRole: Role, required: Role): boolean {
  return roleHierarchy[userRole] >= roleHierarchy[required];
}

export function canSeePatientPHI(role: Role): boolean {
  // bd_rep sees only org/contact; NOT full patient PHI
  return role === "admin" || role === "intake";
}
```

## Acceptance criteria

- [ ] Unauthenticated user visiting `/dashboard` is redirected to `/login`
- [ ] Clicking "Continue with SSO" redirects to WorkOS-hosted auth
- [ ] Successful login returns to `/dashboard` with user email visible
- [ ] Logout endpoint clears session and redirects to `/login`
- [ ] MFA is enforced for admin role (configure in WorkOS dashboard)
- [ ] A user NOT in `crm.users` table gets redirected to `/unauthorized`
- [ ] `withTenantContext` helper sets `app.current_tenant` for RLS
- [ ] `hasRole(userRole, required)` correctly returns boolean
- [ ] Session cookie is httpOnly, Secure, SameSite=Strict

## Common issues

- **WorkOS callback URL mismatch** — register `http://localhost:3000/api/auth/callback` AND the Vercel preview URL in WorkOS dashboard
- **Session too large** — WorkOS session includes all user metadata; strip to essentials for cookie
- **MFA not prompting** — set in WorkOS admin UI per connection, not in code
- **RLS "permission denied" after login** — the API route didn't wrap the query in `withTenantContext`
